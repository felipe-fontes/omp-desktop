## The settings app tab

- State `stab = { open, active, section }` in `app-live.jsx` through the pure `OMP_SETTINGS_TAB` (`initial`, `open(state, section?)`, `close`, `selectProject`, `setSection`, `cycle`). Never persisted: a launch starts closed. `close` resets the section to `appearance`.
- Not a session: no omp process, not in `sessionRegistry`, `open-tabs.json` or the project sidebar, not draggable. `TabBar` (`design/chrome.jsx`) pins it after the project tabs (cog, "Settings", a chip with `modifiedCount("all", t, keyOpts)`, hidden at 0, ×; middle-click closes). While it is active, `activeId` is `null` for the tab bar and sidebar; the omp tab stays `activeSessionId` and the bridge keeps following it, so closing or leaving settings returns to it.
- Host: `<div className="st-host" hidden={!stab.active}>` inside `.stage`, mounted while `stab.open`. Behind a project tab the page stays mounted (search, section and scroll kept) with the last ctx copied as `active: false`; the ctx is rebuilt only while the tab is active, so streaming frames re-render nothing there.
- Open/activate: toolbar cog (`Toolbar` `settings.onOpen`, pressed while `settings.active`), `desktop.settings.open` (`ctrl+,` / `super+,`, not `fromGuest`), `/settings` (desktop-local, shadows omp's own `/settings`; `/tweaks` is gone, no alias). `desktop.shortcuts.open` (`Ctrl+/`) and `/shortcuts` open section `shortcuts`.
- Leaving: any omp tab activation (pick, open, restore, i.e. an `activeSessionId` change) runs `selectProject` (open, inactive). `desktop.tab.close` (Ctrl+W) closes the settings tab while it is active, else the omp tab. `desktop.tab.next` / `prev` use `cycle(stab, sessionIds, activeId, dir)`: settings is the last stop while open.
- `app.interrupt` never fires while `stab.active`. The page listens on `window` in the capture phase, only while active and only for keys aimed at the page (dialogs on top handle their own): Escape is `preventDefault`ed (the keymap skips default-prevented events) but not stopped; it clears the search unless an element marked `data-st-esc` exists (an open row menu, the shortcut recorder), which handles Escape itself. While such an element exists the page's other keys are left to it too. Ctrl/⌘+F focuses the search; ←/→ outside text fields switch sections. Activating the tab focuses the search field, so keys never reach the hidden composer. A section change (including opening on one, e.g. Ctrl+/) clears the search. Leaving the tab ends shortcut recording.

## Schema (`OMP_SETTINGS`)

- `SECTIONS` in order: appearance, layout, chat, composer, rail, terminal, browser, agent, session, remote | approvals (`sep: true`), shortcuts. Each has `id`, `icon`, `title`, `blurb`, `groups` (`name`, optional `src` file chip, `rows`).
- Row kinds: `tweak` (one `TWEAK_DEFAULTS` key; `type` toggle | seg | slider | themes | swatches; rendered by `page.jsx`) and `custom` (`id` `custom:<type>`, rendered by `window.OMP_SETTINGS_ROWS[type]` as `<Comp row ctx query modified onReset />`, showing the schema row's `label` and `desc` plus runtime text of its own; `version` shows runtime text as its desc, `shortcuts` only its editor). Custom renderers register from `rows-layout.jsx` (`widths`, `widgets`, `railOrder`), `rows-programs.jsx` (`shell`, `terminalHeight`, `chromium`), `rows-agent.jsx` (`startupProfile`, `goalContinue`), `rows-session.jsx` (`version`, `keepAwake`), `rows-worktrees.jsx` (`worktrees`), `rows-remote-server.jsx` (`remoteServer`, `remoteCert`), `rows-remote-phones.jsx` (`remotePair`, `remoteDevices`, `remotePush`), `rows-approvals.jsx` (`approvalMode`, `approvalRules`) and `shortcuts-editor.jsx` (`shortcuts`). Both remote row families use the single shared listener, queue and controls in `rows-remote-shared.jsx`.
- A custom row names the tweak keys it owns (`keys`, or `keyPrefix` + `prefixDefault` for `widget:*`), so its changes count in badges and resets. With `opts.prefixKeys` (app-live passes the rendered plugin and extension switch keys as ctx `keyOpts`) only those prefix keys count, so a stored key of a removed plugin never does. Rust-backed rows own none and never count; they show their reset without the changed dot (`SettingsRow resettable`).
- Helpers: `rows`, `value` (fold modes resolved, numbers clamped), `clamp`, `visible` (a row's own `visibleIf`: `collapseAfter` only while a fold mode is `auto`), `isModified(row, values, opts?)` (accent compares with the current theme's own, `themeAccent`, through `OMP_ACCENT.sameColor`), `resetRow(row, values, opts?)`, `modifiedCount(section | "all", values, opts?)`, `resetRows(rows, values, opts?)` and `resetEdits(section | "all", values, opts?)` (rows see earlier edits, so a theme reset settles the accent), `search(query, values)` (label + desc + `kw` + runtime `moreKw`, case-insensitive, grouped `Section › Group`, per-section counts; the shortcuts row matches every action label and id). Bounds of `collapseAfter` / `promptHistoryLimit` / `pasteCollapseLines` and the fold modes are read late from `OMP_COLLAPSE` / `OMP_PROMPT_HISTORY` / `OMP_SESSION_UI`.
- Rendering: search hits are highlighted by splitting text into nodes and `<mark>`; backticks in a schema `desc` become `<code>`; no HTML strings are injected. Sliders commit on release. Picking a different theme resets `accent` to the theme's own; picking the current one again does nothing. Badges show changed counts, or match counts while searching. The footer resets the section, or while searching only the matched rows ("reset matches to defaults").

**Rail → Background tasks** uses `showBackgroundTasks` in the same built-in card inventory and persisted order as Ambient controls. It changes presentation only: observation and native task execution continue when the card or rail is hidden. Pending-input reminders remain attached to the composer and are not hidden by this switch.

## Behaviours

`live.js` reads `restoreTabs`, `confirmBusyClose`, `autoName`, `autoRetry` at load (`PREFS.fromTweaks(OMP_TWEAKS_STORE.read(), TWEAK_DEFAULTS)`: a missing or non-boolean value is the default); `app-live.jsx` keeps them current through `OMP_BRIDGE.setSessionPrefs` (only changed keys act). The obsolete Desktop-wide `autoCompaction` key is discarded; compaction belongs to native profile settings instead.

- **restoreTabs** (default on). Off: `_restoreOpenTabs` opens nothing and leaves `open-tabs.json` as it is; arming adopts the empty layout as written, so the file is first rewritten at the first real tab change (`reopening-tabs.md`).
- **confirmBusyClose** (default off). On, closing a busy tab (`OMP_TURN_STATUS.isBusyRunState`: running, retrying, waiting-user, background) asks first: the tab bar's close goes through `closeSessionGuarded` (`closeSession` stays unconditional). Quitting with busy tabs asks too. `_syncCloseGuard` arms Rust's `CloseGuard` through `set_close_guard` exactly while `closeGuardArmed` (setting on and a tab busy); armed, `handle_run_event` prevents the main window's `CloseRequested` and an `ExitRequested` without code, and emits `window://close-requested`; `live.js` answers with `_requestQuit`. Our own close buttons call `_requestQuit` directly. A confirmed quit disarms the guard, then closes the window, so the exit takes the usual `kill_child_processes` path. The dialog is `design/confirm-close.jsx` over the snapshot's `closeConfirm` (`tabCloseConfirm` / `quitConfirm` shape); `resolveCloseConfirm(ok)` answers it; a newer request replaces one on screen (which resolves false).
- **autoName** (default on). Off: the auto `/rename` and its refreshes are not sent; the arming state is untouched, so turning it back on resumes for tabs still armed. A manual `/rename` is unaffected (`session-title.md`).
- **autoRetry** (default on). At spawn (`_initFetch`, next to the ask-dialog assert) `set_auto_retry` `{enabled: false}` goes out only when the Desktop setting is off, so with it on omp's own config decides. A change goes to every live process (`_sendToAll`) with the new value either way. Context-policy changes do not use this Desktop preference path.
- **submitKey** (`enter` | `ctrl+enter`). `window.isSubmitKey(e, pref)` (`app/constants.js`) for the multi-line fields only: composer, ask-bubble editor, subagent steer box. `enter`: Enter without Shift sends. `ctrl+enter`: Ctrl/⌘+Enter (no Shift/Alt) sends, plain Enter is a newline; the composer checks the send chord before the `app.message.followUp` match. The slash menu's Enter still picks a command. Single-line inputs (rename, profile name, ask-dialog single-line) keep `isSubmitEnter`. The composer hint follows the setting.
- **dictationSend** (default off). `app-live.jsx` `requestDictationAction("stop")` passes it as `OMP_BRIDGE.dictationStop({ send })`; `live.js` tags that capture's completion `send: true` (`_dictationSendCapture`). Stops the bridge makes itself (tab switch, Settings, close, respawn) never pass it. The composer appends the text as usual and, while that tab is shown, sends the draft through `sendWith(onSend)` once the rendered draft ends with the dictated text.
- **dictationAutoStop** (`0` = off | 1.5 | 2 | 3 | 5 s, default 3, room for a thinking pause). `OMP_LIVE_VOICE.DICTATION.autoStopDelay(dictation, seconds)` is the timer: only while the capture is `recording` and has text (no timer before the first words), re-armed by every text change (omp sends new text only for sound its endpointer takes as speech, so the app needs no audio levels). When it fires, `app-live.jsx` calls `requestDictationAction("stop")`, the user's own stop, so `dictationSend` applies.
- **voiceSpectrumBands** (16 | 32 | 48 | 64 | 96 | 128, default 64). Bars of the composer's microphone equalizer, passed to Rust as `voice_spectrum_start { bands }` (`voice-spectrum.md`); a change while it runs restarts the reader with the new count. The Composer section's **Voice** group holds it with `dictationSend` and `dictationAutoStop`.
- **startScreen** (`matrix`, `latent`, `sampling`, `orbit`, `neural`, `attention`). Settings → Appearance presents live preview tiles for the empty workspace; reduced-motion users see a frozen frame. The backdrop and renderer lifecycle are described in `session-model.md`.
- **pasteCollapseLines** (2–50, default 5). `OMP_SESSION_UI.shouldCollapsePaste(raw, maxLines)`; the 500-character cap stays.
- **followOutput** (default on). `OMP_SCROLL_PIN.afterOutput({pinned, follow, repin}, metrics)`: off, new output never scrolls; content pushed past the bottom unpins ("Jump to latest" shows). A sent prompt, a transcript reset and the first render still jump to the latest.
- **terminalScrollback** (1000 | 5000 | 10000 | 50000, default 5000). `OMP_TERMINAL_XTERM.scrollbackLines(pref)` (0–100000) at xterm creation; `useTerminal` applies a change to existing terminals.
- **defaultSide** (`rail` | `tree` | `browser`). `app-live.jsx` seeds a tab's side column with `OMP_SESSION_UI.seedEntries` the first time its id is seen (`seenSideIds`; restored tabs count as new); `rail` stores nothing. Changing the setting never moves open tabs.
- **Accent.** `useThemeEffect` (`app/use-bridge-snapshot.jsx`) clears `--accent`, `--accent-soft`, `--accent-glow`, `--accent-deep`, then, when the accent differs from the theme's own, sets all four from `OMP_ACCENT.accentTokens` (soft 12% / glow 45% alpha as `rgba()`, deep = 25% black; xterm reads `--accent-soft` uncomputed, so no `color-mix()`).
- **Updates.** The `version` row shows the version and last check, "Check now" (`updater.check`) and the skipped release with "Clear skipped" (`updater.clearSkipped`).
- **Approvals.** The `approvalMode` row renders the same `ApprovalModeSection` as the approvals panel; `approvalRules` shows the rule count and opens the panel.
- **Shortcuts.** `shortcuts-editor.jsx` is the rebinding editor (formerly the shortcuts modal): rebind, add a chord, clear, reset to default; rows from omp's `keybindings.yml` can be overridden too; the source chip shows where a binding comes from.

## Keep computer awake

The status bar's **Keep computer awake** control applies only to its chat. **Use default** clears that chat's override. **Settings → Session → Power → Keep computer awake by default** changes the app-wide default, initially off, for open and future inheriting chats across every profile. Explicit on/off overrides remain independent. Reset beside the row restores the default to off without clearing those overrides. Opening the page only reads native state.

The choice is **while the agent is working**, not while a tab merely remains open. Rust's all-tab tracker supplies busy state, including background chats; a non-yielding continuation and an in-flight tool question do not end the run. A yielding end or process exit removes that chat's work from the aggregate. One native inhibitor is held while any registered, effectively-enabled tab is busy. Tab close, webview reload, shutdown and updater relaunch remove ownership and release the last request. An omp respawn under the same tab id retains its override; closing/reloading the tab does not persist it into a later conversation.

The native keep-awake manager owns the settings, tab registry, coalesced worker and OS handles. It sits in the existing tracker sink chain without replacing notifications or remote access. The stdout callback only marks dirty state and wakes the worker; it performs no OS/file I/O or tab scans. Global writes are strict and run off IPC; without an app config directory the default is memory-only. Unreadable settings refuse overwrites.

`keep_awake_snapshot`, `keep_awake_set_default` and `keep_awake_set_session` return revisioned snapshots; `keep-awake://changed` publishes changes. Each snapshot contains `defaultEnabled`, actual native `active`, `error` and per-tab `overrideEnabled`, effective `enabled` and `working`. The frontend subscribes before its first read, ignores stale revisions and binds pending actions/errors to their originating tab. An enabled-but-idle chat is not shown as actively inhibiting sleep. Acquisition/release failures stay explicit rather than claiming success; failed releases retain owned requests for a later real transition. There is no retry timer.

macOS uses IOKit idle-display and idle-system assertions, Windows uses the worker thread's execution state, and Linux uses the freedesktop ScreenSaver and logind inhibition APIs with bounded D-Bus calls. These are native idle-inhibition requests, not simulated input, screen-unlock commands or power-policy edits. Manual locking, lid-close/forced sleep and managed security policies remain authoritative ([Apple's assertion contract](https://developer.apple.com/library/archive/releasenotes/Darwin/RN-IOKitPowerManagment/index.html)). The UI reports an unavailable/denied native service as an error.

Coverage includes policy precedence, multiple working tabs, process/close/reload ownership, persistence failures, worker acquisition/release failures and stale UI actions. The opt-in macOS manager/tracker probe permits inspecting only its PID and `OMP Desktop agent work` reason in `pmset -g assertions`, both while held and after release; other apps can independently keep the machine awake.

## Desktop notifications

**Settings → Session → Desktop notifications** has independent **Conversation finished** (`notifyFinished`) and **User input needed** (`notifyQuestions`) switches, both off by default. They use the normal tweaks store, modified count, search and reset. The custom notification row owns both keys. These are local OS alerts, not Remote access's phone Web Push: no pairing, server, HTTPS certificate, VAPID contact or APNs entitlement is involved.

The first enable on macOS calls native `UNUserNotificationCenter.requestAuthorization` for alerts. Opening Settings only reads authorization; restoring saved preferences never requests it. A switch is saved on only after authorization succeeds. Denial leaves it off and explains **System Settings → Notifications → OMP Desktop**; macOS will not reopen its prompt after a denial. Returning from system settings refreshes authorization. An in-flight request disables both controls; resetting or unmounting invalidates its pending enable choice. Windows/Linux have no equivalent per-app authorization popup and defer to their system notification settings. Focus / Do Not Disturb can suppress banners on every platform.

macOS uses `UserNotifications` for permission and local delivery, with a retained foreground-presentation delegate for alerts from another tab. A bundled, ad-hoc-signed `.app` is sufficient; Developer ID signing/notarization is not required for local alerts. Unbundled development executables report permission as unavailable instead of calling the native API that raises an Objective-C exception without an app bundle. Windows/Linux use the Tauri notification plugin. Successful submission is not proof of OS display.

`useNotifications` sends only preferences, bounded tab names and the viewed conversation through `desktop_notifications_configure`; it does not infer events from frontend state, polling or journal replay. `desktop_notifications_permission {request}` reads or explicitly requests native permission. The native dispatcher reuses the all-tab remote tracker: one alert for a newly opened ask/select/confirm/input/editor request, or a terminal yielding end after an agent start. Duplicate frames, auto-approved requests and non-yielding continuation ends do not create alerts. The currently viewed conversation is quiet while the main window is focused; Settings covering it is not viewing it. Native focus events maintain a bit so the worker never waits on the window thread during shutdown.

The reader only tries a bounded queue and never waits on native delivery or configuration work. The worker rechecks preferences, configuration revision, tab membership and current tracker state: closed/restarted tabs, answered/cancelled questions and invalidated queued alerts are skipped. A full queue or contended configuration skips an optional alert rather than delaying the agent. Notification text is a bounded tab title plus a fixed finished/input-needed message, never transcript or tool contents. macOS replaces the previous alert for that tab. A page load resets configuration until the new document publishes it; app shutdown stops and joins the worker before ending agents.

Regression coverage: native notification tests cover opt-in, focus, lifecycle, deduplication, queue pressure and invalidation; macOS tests cover authorization states and the unbundled prerequisite. `test-desktop-notifications.mjs` covers permission-pending, grant, denial, errors and discarded enable choices.

Verification on macOS: an isolated ad-hoc-signed release app rendered the real Settings row, read undetermined authorization without prompting, and entered the native permission-waiting path only after its switch was clicked; its saved preferences stayed off while permission was pending. Controlled RPC frames exercised a yielding end and a confirm request through the real native reader. Browser interaction covered granted/denied/error outcomes using injected permission responses. The AppKit/WKWebView geometry probe put traffic-light centres at 18.5pt for the fixed 38px toolbar. Screen Recording and Accessibility permissions prevented a native screenshot, automated response to the OS prompt, and visual banner/tiling verification; those are not claimed as exercised.

The former gauge and Agent context cards retain their single migrated visibility/order identity. The rail shows usage, the effective compaction target, cost and throughput once. **Inspect context** opens inventory and a secondary token-breakdown disclosure. Search, skill-use filter and selected agent are per-tab UI state and clear when that tab closes, not persisted conversation data.

### Native context policy

The Context ring and **Settings → Agent → Context and compaction** share one editor and native snapshot. Activating the compact gauge replaces it with the enlarged edit surface, not a second summary. The inner arc is usage; the bounded outer marker is the target. Pointer dragging, track clicking, exact percentage entry and arrows/Home/End/Page keys change only a draft. The centre, inner usage arc and sweep gap cannot start a drag; pointer cancellation restores its initial draft. Explanations use hover/focus help, while conflicts and above-target warnings remain visible. Saving scope choices appear only after a change.

Targets use a percentage of the active native model window, with the resolved token threshold shown alongside it. **Save for this conversation** persists a target keyed by provider/model on the native session branch. **Set default for this model in the named profile** uses the exact key in native `compaction.modelThresholds`, leaving other model keys and wildcard policies intact. Model switching and reopening restore separate targets. **Use profile setting** removes only the selected model's conversation target, with inherited read-back previewed before saving. Existing native token/base rules and version-1 broad conversation overrides remain effective until explicitly edited; new branch metadata is version 2 and bounded to 128 model targets. Native defaults are inherited for unconfigured models, not replaced with guessed quality targets.

The private bundled extension registers an epoch-specific local command, discovered before sending through ordinary RPC command dispatch. Correlated private notifications are consumed before chat, ask, remote-view or extension-widget rendering. Writable values are `targetPercent` (a number, or null to remove the selected model target), `enabled`, `method`, `asyncEnabled` and `midTurnEnabled`. The last four are conversation/profile-wide, not per-model. Disabling also sets native idle compaction off at that scope atomically, retaining targets; re-enabling does not silently opt idle compaction back on. Manual compaction and ordinary pruning remain independent. Advanced shows preferred method/native fallbacks, background preparation and safe mid-turn checks. No model messages, provider requests, YAML editing in Desktop, extra compaction scheduler, polling timer or pre-compaction interception hook is involved.

The native process binds the selected profile, validates scope/model/revision and native retained-tail/prompt-headroom bounds, flushes saved writes, and reports the actual effective result/source. A profile save never silently removes a conversation override or claims a shadowed value took effect. Conversation writes materialize and flush even a new empty native session before success, with rollback on persistence failure. Native effective-setting listeners and lifecycle events publish changes. Inherited previews exclude only runtime overrides still owned by this extension; other extensions' writes are retained. Ownership/generation guards cover asynchronous reads, model changes and stale writes. Dirty drafts cannot be saved onto a new conversation/model or over external changes; Use latest explicitly discards them. Unsupported capabilities disable editing. Editing and reset never restart a process or send a manual compact command, although an enabled/lowered target can affect the next eligible native maintenance check.

Post-save confirmation uses the bounded same-conversation/model snapshot retry used for refreshes. A native reload may cause the read to retry, but persistence and appends are never replayed. Changed ownership/model and ordinary read failures still reject.


## Ambient rail: Changes and Auto-fix

The original owner's **Changes** card, PR parser and automation controller are authoritative. The card shows the checked-out branch's open PR, draft state, diff counts, links and full CI progress. Its menu owns the only Auto-fix toggle. Disconnected, loading, no-PR and lookup-error states retain the owner's placeholders and error presentation; non-Git folders and missing upstream configuration are not silently treated as successful empty lookups.

Local changed-file counts extend that card independently of GitHub authentication. Staged, unstaged and untracked non-ignored changes count against the actual checkout's HEAD and link to the existing Git browser. Counts reuse its safe gix status merge without building a file tree or upstream graph; a capped count says **At least**. Missing `gh` hides the PR-only card, but a positive local count keeps the card available. Local errors retain a relevant last-known count and label it accordingly.

Native `changes_snapshot` resolves the folder from the registered tab and returns an optional `{changed, truncated}` result. Native `pr_automation_snapshot` separately uses authenticated GitHub CLI and returns the canonical open-PR snapshot: identity/display metadata, all CI checks, failed-check identities and actionable review-thread identities. It requires a configured GitHub.com upstream, a live remote ref and matching local/remote HEAD. It does not expose the removed personal all-lifecycle discovery protocol or its `state`/`checksState` fields.

PR reads and remediation use only the selected, settled tab. Switching tabs, changing branch or replacing a conversation/process invalidates in-flight results; `STALE` means retry later, never **no PR**. The hook caches canonical snapshots for project-navigation check/review indicators and invalidates them when their originating identity changes. Navigation does not start a second poller or refresh inactive tabs.

The controller serializes PR reads. Selection, readiness, conversation/branch changes, focus and explicit refresh can trigger a read. Periodic reads run every thirty seconds with Auto-fix enabled; queued/running CI refreshes every fifteen seconds even with Auto-fix off while visible. Completed CI without an opt-in does not poll indefinitely. Hidden cards/documents stop display-only reads; enabled selected-tab automation can continue. Retryable native errors use the owner's bounded exponential backoff; ordinary lookup errors remain visible, and automation pauses after an error until explicitly disabled and re-enabled. Missing `gh` revokes the grant and waits for a refresh.

**Settings → Rail → Built-in cards → Changes** uses the existing `showChanges` tweak. Off hides the card and navigation indicators, cancels pending reads/dispatch and revokes every tab's Auto-fix grant. Turning it back on never restores permission. Search, modified counts and reset use the ordinary schema helpers.

Auto-fix is off by default, per tab and memory-only. Enabling another tab on the same canonical folder disables the earlier grant. Inactive tabs cannot start fixes. The bridge requires strict native idle/settled state, no pending messages, no goal run and no busy sibling on the same folder, then re-reads the native PR snapshot and matches URL, branch and HEAD immediately before handing off an ordinary visible prompt. Plan/goal modes and Settings also block dispatch. Stop and stop-retry disable the grant; work already handed to omp cannot be recalled.

Only failed completed checks and unresolved, non-outdated review threads produce fix prompts. Check identities include PR, HEAD and attempt timestamps; thread identities include PR, thread id and the latest external-comment timestamp, independently of HEAD. An unchanged item is submitted once per enabled incarnation. A submitted prompt is not proof of a fix, and no failed checks does not mean pending checks passed.

The agent must revalidate branch and HEAD, inspect fresh logs/comments, fix and verify relevant issues, commit and push normally, then reply to and resolve only threads actually addressed. Impossible or unrelated concerns remain unresolved. Remote text is data, never authority to bypass approvals, force-push or merge. Existing tool approvals remain in effect.

Regression coverage: `test-pr-automation.mjs` covers controller readiness, CI progress, retry/backoff, stale ownership and feedback identities; `test-pr-automation-bridge.mjs` covers active-only reads and fresh validated handoffs; `test-pr-status.mjs` covers cached navigation indicators. Native tests cover identity selection, local revalidation, bounded feedback and supervised GitHub requests. The ignored `live_read_only_snapshot` probe accepts `OMP_PR_AUTOMATION_SMOKE_PROJECT` and reads Git metadata/GitHub without mutations. Each GitHub connection is capped at one hundred results and rejects truncation. Live remediation is not implied by those tests.

## Conversation worktree storage

**Session → Workspace storage → Conversation worktrees** is a native-backed row, not a localStorage tweak. It shows retained checkout count, measured checkout bytes, separately reported restore-point bytes, each lease/pin state and recovery errors. Unmeasured sizes say **Checkout size not measured**; incomplete totals say **at least**. Measurement failure does not erase an independent capture or notification error.

**Save limits** validates positive whole-number count and byte budgets. Defaults are fifteen retained checkouts and 20 GiB of measured checkout data; the thirty-day inactivity lease is not shortened by budget changes. An over-budget state is advisory, never permission to delete active, pinned or unexpired work. Restore points are not automatically removed by these budgets.

**Refresh sizes** measures directory trees off-thread, outside the lifecycle guard, then applies results only to the same checkout generation. Metadata reads and refreshes do not renew inactivity. **Check due worktrees now** uses the same native ownership, expiry and verified-snapshot path as the automatic worker; it is not force-delete. **Pin/Unpin** persists native protection. **Restore** reconstructs files and records explicit use but does not open an agent or conversation.

The hook subscribes to native changes before reading state and retains actionable loading, measurement and mutation errors separately. Rust derives paths and ownership; the webview sends ids, a typed close action or validated budgets, never a deletion path. Full close, restore, cache-coverage and background-expiry rules are under [Disposable conversation worktrees](session-model.md#disposable-conversation-worktrees).
